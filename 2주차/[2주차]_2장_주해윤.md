## 2장 개략적인 규모 추정

---

> 개략적 규모 추정은 보편적으로 통용되는 성능 수치상에서 사고 실험을 행하여 추정치를 계산하는 행위로서, 어떤 설계가 요구사항에 부합할 것인지 보기 위한 것
> 

→ 이를 효과적으로 해 내려면 규모 확장성을 표현하는 데 필요한 기본기에 능숙해야 함

### 1) 2의 제곱수

- 데이터 볼륨의 단위를 2의 제곱수로 표현한다면?
    
    
    | 2의 x 제곱 | 근사치 | 이름 | 축약형 |
    | --- | --- | --- | --- |
    | 10 | 1천 | 1킬로바이트 | 1KB |
    | 20 | 1백만 | 1메가바이트 | 1MB |
    | 30 | 10억 | 1기가바이트 | 1GB |
    | 40 | 1조 | 1테라바이트 | 1TB |
    | 50 | 1000조 | 1페타바이트 | 1PB |
- 데이터의 최소 단위: 1바이트, 8비트로 구성됨

### 2) 모든 프로그래머가 알아야 하는 응답지연 값

- 2020 기준 기술 동향을 반영한 수치

| 연산명 | 시간 |
| --- | --- |
| L1 캐시 참조 | 1ns |
| 분기 예측 오류 | 3ns |
| L2 캐시 참조 | 4ns |
| 뮤텍스 락/언락 | 17ns |
| 일반 상용 네트워크상에서 2K바이트 전송 | 44ns |
| 주 메모리 참조 | 100ns |
| Zippy로 1kb 압축 | 2000ns |
| 메모리에서 1M바이트 순차적 읽기 | 3000ns |
| SSD상에서 임의 위치의 데이터 읽기 | 16000ns |
| SSD에서 1M바이트 순차적 읽기 | 49000ns |
| 동일 데이터 센터 내에서의 패킷 왕복 지연시간 | 500000ns |
| 디스크에서 1M바이트 순차적 읽기 | 825000ns |
| 디스크 탐색 | 2000000ns |
| CA에서 네덜란드까지의 패킷 왕복 지연시간 | 150000000ns |
- 표를 통해 나오는 결론
    1. 메모리는 빠르지만 디스크는 아직도 느림
    2. 디스크 탐색은 가능한 한 피할 것
    3. 단순한 압축 알고리즘은 빠름
    4. 데이터를 인터넷으로 전송하기 전에 가능하면 압축할 것
    5. 데이터 센터는 보통 여러 지역에 분산되어 있고, 센터들 간에 데이터 주고 받는 데에 시간이 걸림

### 3) 가용성에 관계된 수치들

- 고가용성: 시스템이 오랜 시간 동안 지속적으로 중단 없이 운영될 수 있는 능력
    - 퍼센트로 표현, 대부분의 서비스가 99-100% 사이의 값 가짐
- SLA(Service Level Agreement): 서비스 사업자와 고객 사이에 맺어진 합의
    - 서비스 사업자가 제공하는 서비스의 가용시간 공식적으로 기술

### 4) 팁

- 근사치를 활용한 계산: `99987/9.1` →`100000/10` 처럼 근사치를 활용하여 시간 절약
- 나중에 살펴볼 수 있도록 가정을 적어둘 것
- 단위를 붙일 것
- 많이 출제되는 개략적 규모 추정 문제: QPS, 최대 QPS, 저장소 요구량, 캐시 요구량, 서버 수 등을 추정
    - *QPS: Query Per Second, 시스템이나 서버가 1초 동안 얼마나 많은 요청을 처리할 수 있는지
