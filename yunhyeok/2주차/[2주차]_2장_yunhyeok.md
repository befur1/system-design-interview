# 개략적인 규모 추정 (Back-of-the-envelope Estimation)

1 byte = 8bit
ASCII code 'A' = 메모리 크기로 1byte에 해당한다.

2**10 = 1KB
2**20 = 2MB
2**30 = 1GB
2**40 = 1TB
2**50 = 1PB

통상적인 컴퓨터에서 구현된 연산들의 응답지연 시간을 통해 알 수 있는 사실들

1. 메모리는 빠르지만, 디스크는 느리다.
2. 디스크 탐색은 가능한 피하라.
3. 단순한 압축 알고리즘은 빠르다.
4. 데이터를 인터넷으로 전송하기 전에 가능하면 압축하라.
5. 데이터 센터는 보통 여러 지역에 분산되어 있고, 센터들 간에 데이터를 주고받는 데는 시간이 걸린다.

가용성에 관계된 수치들.

1. 100%는 시스템이 단 한 번도 중단된 적이 없었음을 의미한다.
2. 99~100% 사이의 값이 대부분의 서비스가 갖는 값이다.
3. 9가 많을 수록 응답 장애 시간이 적어진다.

가용률 99.99% -> 하루당 장애시간 8.64초
가용률 99.9% -> 하루당 장애시간 1.44분

개략적 규모 추정에서의 팁.

1. 근사치를 활용한 계산을 진행해라 -> 너무 작은 숫자에 시간낭비 하지 말자.
2. 가정한 내용이 있다면 적어두자.
3. 단위를 붙여라 -> 여기서 단위는 생명이다. mb,kb 다르다.
4. 많이 출제되는 개략적 규모 추정 문제는 QPS, 최대 QPS, 저장소 요구량, 캐시 요구량, 서버 수 추정
   등이 있다.

## 한 줄 요약

> 정확한 숫자가 아니라 "자릿수 감각"을 잡기 위해, 알고 있는 기준값(2의 제곱수, 지연 시간)을 이용해 곱셈만으로 시스템 규모를 어림잡아보는 것.

## QPS 에 대해서
1. QPS는 Queries Per Second의 약자로, 초당 처리하는 요청(쿼리) 수를 뜻한다. 
2. 시스템이 1초 동안 몇 건의 요청을 받아 처리하는지를 나타내는 지표로
웹 서버나 API, 데이터베이스의 처리량(throughput)을 이야기할 때 가장 많이 쓰인다.
