## 5장 요약

### 해시 키 재배치 문제

N개의 캐시 서버가 있을 때, 부하를 균등하게 나누는 보편적 방법은 아래의 해시 함수를 사용

```sql
serverIndex = hash(key) % N
```

위와 같은 방식은 서버 풀의 크기가 고정되어 있을 때, 데이터 분포가 균등할 때는 잘 작동

But, 서버가 추가되거나 기존 서버가 삭제되면 N값이 변경되어서 키의 재분배가 일어나게 됨

→ 그러면 캐시 클라이언트가 데이터가 없는 엉뚱한 서버에 접속하는 대규모 캐시 미스가 발생함

### 안정 해시

안정 해시는 해시 테이블 크기가 조정될 때 평균적으로 k/n개의 키만 재배치하는 해시 기술 (k는 키의 개수, n은 슬롯의 개수)

#### 해시 공간과 해시 링

SHA-1을 사용하는 해시 함수 f, 그 함수의 출력 값 범위는 x0 ~ xn까지이며 SHA-1의 해시 공간 범위는 0부터 2^160 - 1이니 x0는 0, xn은 2^160 - 1의 값을 가지게 되고 이 공간 범위를 원으로 만들면 해시링이 됨

#### 해시  서버 & 해시 키

해시 함수 f에 입력 값으로 서버 IP나 이름을 넣으면 결과 값으로 이 링 위에 서버가 배치 됨 + 키 값에 해시 함수 f를 적용해서도 이 링 위 어느 지점에 배치가 됨

#### 서버 조회 & 추가 & 삭제

해시 링에서 키가 저장 되는 서버는 해당 키의 위치로부터 시계 방향으로 탐색했을 때 가장 가까운 첫 번째 서버

추가 or 삭제 시에는 일부 카만 재배치하면 되서 유용함

#### 기존 구현법의 문제

안정 해시 알고리즘은 MIT에서 제안되었음. 기본 절차로는

- 서버와 키를 균등 분포 해시 함수를 사용해 해시 링에 배치
- 키의 위치에서 링을 시계 방향으로 탐색하다 만나는 최초의 서버가 키가 저장될 서버

로 제안되었는데 이 접근법에서는 두 가지 문제가 발생

1. 파티션의 크기(해시 공간의 크기)를 균등하게 유지하는 게 불가능 함

→ 서버가 추가되거나 삭제되는 상황에서 불균등이 발생함

1. 키의 균등 분포를 달성하기가 어려움

→ 시계 방향에서 가장 가까운 서버에 키가 저장되는 구조여서 서버 하나에 키 여러 개가 저장될 수 있음

#### 가상 노드

가상 노드를 사용해서 각 서버는 여러 개의 파티션을 관리하게 되는데, 가상 노드의 개수를 늘리면 키의 분포가 점점 더 균등해짐 ← 표준 편차가 작아져서 데이터가 고르게 분포되기 때문임

But 가상 노드를 무작정 늘리다가 보면 저장할 공간은 더 많이 필요하게 됨. 적절한 트레이드 오프가 필요하다는 것을 의미

- 안정 해시는 서버가 추가되거나 삭제될 때 재배치되는 키의 수가 최소화
- 데이터가 보다 균등하게 분포하게 되어 수평적 규모 확장성 달성에 유리
- 핫스팟 키 문제를 줄임 → 특정한 샤드에 대한 접근에 대한 접근이 빈번하면 서버에 과부하 문제가 발생하는데 안정 해시는 데이터를 좀 더 균등하게 분배
