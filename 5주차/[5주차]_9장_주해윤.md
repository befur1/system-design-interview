## 9장 웹 크롤러 설계

---

> 웹 크롤러는 로봇 또는 스파이더라고도 부르며, 웹에 새로 올라오거나 갱신된 콘텐츠를 찾아내는 기술이다. 몇 개의 웹 페이지에서 시작해 링크를 따라가면서 새로운 콘텐츠를 수집한다.
> 

### 문제 이해 및 설계 범위 확정

- 웹 크롤러의 용도
    - 검색 엔진 인덱싱: 웹 페이지를 모아 검색 엔진을 위한 로컬 인덱스를 만듦
    - 웹 아카이빙: 장기 보관을 위해 웹에서 정보를 모음
    - 웹 마이닝: 인터넷에서 유용한 지식을 도출
    - 웹 모니터링: 인터넷에서 저작권이나 상표권이 침해되는 사례를 감시
- 웹 크롤러의 기본 알고리즘
    1. URL 집합이 입력으로 주어지면 해당 URL들이 가리키는 모든 웹 페이지를 다운로드한다.
    2. 다운로드한 웹 페이지에서 URL을 추출한다.
    3. 추출된 URL을 다운로드할 URL 목록에 추가하고 위의 과정을 반복한다.
- 설계 범위
    - 검색 엔진 인덱싱에 사용
    - 매달 10억 개의 웹 페이지 수집
    - 새로 만들어지거나 수정된 웹 페이지도 고려
    - 수집한 웹 페이지를 5년간 저장
    - 중복된 콘텐츠는 무시
- 좋은 웹 크롤러가 만족해야 하는 속성
    - 규모 확장성: 병행성을 활용해 효과적으로 웹 크롤링
    - 안정성: 잘못 작성된 HTML, 응답이 없는 서버, 장애, 악성 코드가 포함된 링크 등 비정상적인 입력이나 환경에 대응
    - 예절: 같은 웹사이트에 짧은 시간 동안 너무 많은 요청을 보내지 않음
    - 확장성: 새로운 형태의 콘텐츠를 쉽게 지원
- 개략적 규모 추정
    - 매달 10억 개의 웹 페이지 다운로드
    - QPS: `10억/30일/24시간/3600초 = 약 400`
    - 최대 QPS: `2×400 = 800`
    - 웹 페이지의 평균 크기: 500KB
    - 월간 저장 용량: `10억×500KB = 500TB`
    - 5년간 저장 용량: `500TB×12개월×5년 = 30PB`
    

### 개략적 설계안 제시 및 동의 구하기

**시작 URL 집합**

- 웹 크롤러가 크롤링을 시작하는 출발점
- 전체 웹을 크롤링한다면 크롤러가 가능한 한 많은 링크를 탐색할 수 있는 URL을 선택해야 함
- URL 공간을 작은 부분집합으로 나누는 전략을 사용할 수 있음
    - 나라별로 인기 있는 웹사이트가 다르다는 점을 고려해 지역별로 구분
    - 쇼핑, 스포츠, 건강 등의 주제별로 URL 공간을 구분
- 어떤 시작 URL을 사용해야 하는지에 대한 정답은 없음

**미수집 URL 저장소**

- 크롤링 상태를 다음 두 가지로 나누어 관리
    1. 다운로드할 URL
    2. 다운로드된 URL
- 다운로드할 URL을 저장하고 관리하는 컴포넌트를 미수집 URL 저장소라고 함
- FIFO 큐로 생각할 수 있음

**HTML 다운로더**

- 인터넷에서 웹 페이지를 다운로드하는 컴포넌트
- 다운로드할 페이지의 URL은 미수집 URL 저장소가 제공

**도메인 이름 변환기**

- 웹 페이지를 다운로드하려면 URL을 IP 주소로 변환해야 함
- 도메인 이름 변환기는 URL에 대응하는 IP 주소를 알아냄

**콘텐츠 파서**

- 웹 페이지를 다운로드하면 파싱과 검증 절차를 거침
- 이상한 웹 페이지는 저장 공간을 낭비하거나 크롤링 과정을 느리게 만들 수 있음
- 콘텐츠 파서를 크롤링 서버 안에 구현하면 크롤링 과정이 느려질 수 있으므로 독립된 컴포넌트로 구성

**중복 콘텐츠 확인**

- 웹에 공개된 연구 결과에 따르면 약 29%의 웹 페이지 콘텐츠가 중복
- 같은 콘텐츠를 여러 번 저장하면 데이터 처리 시간과 저장 공간이 낭비됨
- 두 HTML 문서를 문자열로 직접 비교하는 대신 웹 페이지의 해시 값을 비교

**콘텐츠 저장소**

- HTML 문서를 보관하는 시스템
- 저장 기술을 선택할 때 데이터 유형, 크기, 저장소 접근 빈도, 데이터의 유효 기간 등을 고려
- 데이터가 너무 많으므로 대부분의 콘텐츠는 디스크에 저장
- 인기 있는 콘텐츠는 메모리에 두어 접근 지연시간을 줄임

**URL 추출기**

- HTML 페이지를 파싱하여 링크를 골라냄
- 상대 경로에는 현재 URL을 붙여 절대 경로로 변환

**URL 필터**

- 다음과 같은 URL을 크롤링 대상에서 제외
    - 특정한 콘텐츠 타입이나 파일 확장자를 가진 URL
    - 접속 시 오류가 발생하는 URL
    - 접근 제외 목록에 포함된 URL

**이미 방문한 URL 확인**

- 이미 방문한 URL이나 미수집 URL 저장소에 보관된 URL인지 확인
- 같은 URL을 여러 번 처리하는 것을 방지
- 크롤러가 무한 루프에 빠지는 것을 방지
- 블룸 필터나 해시 테이블을 사용할 수 있음

**URL 저장소**

- 이미 방문한 URL을 보관하는 저장소

**웹 크롤러 작업 흐름**

1. 시작 URL들을 미수집 URL 저장소에 저장한다.
2. HTML 다운로더는 미수집 URL 저장소에서 URL 목록을 가져온다.
3. HTML 다운로더는 도메인 이름 변환기를 사용하여 URL의 IP 주소를 알아내고, 해당 IP 주소로 접속하여 웹 페이지를 다운로드한다.
4. 콘텐츠 파서는 다운로드한 HTML 페이지를 파싱하여 올바른 형식의 페이지인지 검증한다.
5. 콘텐츠 파싱과 검증이 끝나면 중복 콘텐츠인지 확인한다.
6. 중복 콘텐츠인지 확인하기 위해 해당 페이지가 이미 저장소에 있는지 확인한다.
    - 이미 저장소에 있는 콘텐츠라면 처리하지 않고 버린다.
    - 저장소에 없는 콘텐츠라면 콘텐츠 저장소에 저장한 뒤 URL 추출기로 전달한다.
7. URL 추출기는 HTML 페이지에서 링크를 골라낸다.
8. 골라낸 링크를 URL 필터로 전달한다.
9. 필터링이 끝나고 남은 URL만 중복 URL 판별 단계로 전달한다.
10. 이미 처리한 URL인지 확인하기 위해 URL 저장소에 보관된 URL인지 살핀다.
    - 이미 저장소에 있는 URL은 버린다.
11. 저장소에 없는 URL은 URL 저장소에 저장하고 미수집 URL 저장소에도 전달한다.

### 상세 설계

**DFS와 BFS**

- 웹은 유향 그래프와 같음
    - 웹 페이지: 노드
    - 하이퍼링크: 에지
- 크롤링 과정은 유향 그래프의 에지를 따라 탐색하는 과정
- DFS는 그래프 크기가 클 때 어느 정도로 깊숙이 탐색해야 할지 결정하기 어려워 좋은 선택이 아닐 가능성이 높음
- 웹 크롤러는 일반적으로 BFS를 사용
- BFS는 FIFO 큐를 사용하며, 큐의 한쪽에는 탐색할 URL을 집어넣고 다른 한쪽에서는 URL을 꺼냄
- 표준 BFS의 문제점
    - 한 페이지에서 나오는 링크의 상당수가 같은 서버로 돌아갈 수 있음
    - 같은 호스트에 속한 링크를 병렬로 처리하면 해당 서버에 많은 요청을 보내 부하를 줄 수 있음
    - URL 사이에 우선순위를 두지 않으므로 모든 웹 페이지를 같은 수준으로 취급함

**미수집 URL 저장소**

- URL 저장소는 다운로드할 URL을 보관
- 예절을 갖춘 크롤러, URL 사이의 우선순위와 신선도를 구별하는 크롤러를 구현할 수 있음

**예절**

- 웹 크롤러는 같은 웹사이트에 짧은 시간 안에 너무 많은 요청을 보내지 않아야 함
- 동일 웹사이트에서는 한 번에 한 페이지만 요청
- 같은 웹사이트의 페이지를 다운로드하는 작업 사이에는 시간차를 둠
- 웹사이트의 호스트명과 다운로드 작업 스레드 사이의 관계를 유지
- 각 다운로드 스레드는 별도의 FIFO 큐를 가지며 해당 큐에서 꺼낸 URL만 다운로드
- 큐 라우터
    - 같은 호스트에 속한 URL이 항상 같은 큐로 가도록 보장
- 매핑 테이블
    - 호스트 이름과 큐 사이의 관계를 보관
- FIFO 큐
    - 같은 호스트에 속한 URL을 같은 큐에 보관
- 큐 선택기
    - 큐들을 순회하며 URL을 꺼냄
    - 꺼낸 URL을 다운로드하도록 지정된 작업 스레드에 전달
- 작업 스레드
    - 전달된 URL을 다운로드
    - URL을 순차적으로 처리하며 작업 사이에 일정한 지연시간을 둘 수 있음

**우선순위**

- 모든 웹 페이지가 같은 수준의 품질이나 중요성을 갖지는 않음
- 페이지 순위, 사용자 트래픽의 양, 갱신 빈도 등을 기준으로 처리 우선순위를 구별
- 순위결정장치는 URL 우선순위를 정하는 컴포넌트
- 순위결정장치
    - URL을 입력으로 받아 우선순위를 계산
- 전면 큐
    - 우선순위 결정 과정을 처리
    - 우선순위별로 하나씩 할당
- 큐 선택기
    - 임의의 큐에서 처리할 URL을 꺼냄
    - 우선순위가 높은 큐에서 더 자주 꺼내도록 구성
- 후면 큐
    - 크롤러가 예의 바르게 동작하도록 보장

**신선도**

- 웹 페이지는 수시로 추가되고 삭제되며 변경됨
- 데이터의 신선함을 유지하기 위해 이미 다운로드한 페이지도 주기적으로 재수집해야 함
- 모든 URL을 재수집하는 것은 많은 시간과 자원이 필요
- 최적화 전략
    - 웹 페이지의 변경 이력을 활용
    - 우선순위를 활용하여 중요한 페이지를 더 자주 재수집

**미수집 URL 저장소를 위한 지속성 저장장치**

- 처리할 URL의 수가 수억 개에 달하므로 모든 URL을 메모리에 저장하는 것은 안정성과 규모 확장성 측면에서 바람직하지 않음
- 모든 URL을 디스크에 저장하면 디스크가 성능 병목 지점이 될 수 있음
- 절충안을 사용
    - 대부분의 URL은 디스크에 저장
    - 입출력 비용을 줄이기 위해 메모리 버퍼에 큐를 둠
    - 버퍼에 있는 데이터는 주기적으로 디스크에 기록

**HTML 다운로더**

- HTTP 프로토콜을 통해 웹 페이지를 다운로드

**Robots.txt**

- 로봇 제외 프로토콜이라고도 함
- 웹사이트가 크롤러와 소통하는 표준적인 방법
- 크롤러가 수집해도 되는 페이지 목록이 들어 있음
- 웹사이트를 크롤링하기 전에 해당 파일에 나열된 규칙을 먼저 확인해야 함
- 파일을 반복해서 다운로드하지 않도록 주기적으로 다시 받아 캐시에 보관

**성능 최적화**

1. 분산 크롤링
    - 크롤링 작업을 여러 서버에 분산
    - 각 서버는 여러 스레드를 돌려 다운로드 작업 처리
    - URL 공간을 작은 단위로 분할하여 각 서버가 일부 다운로드를 담당
2. 도메인 이름 변환 결과 캐시
    - DNS 요청은 동기적으로 처리되며 보통 10ms에서 200ms가 소요됨
    - 한 스레드가 DNS 요청을 처리하면 다른 스레드의 DNS 요청도 블록될 수 있음
    - 도메인 이름과 IP 주소 사이의 관계를 캐시에 보관
    - 크론 잡 등을 통해 주기적으로 갱신
3. 지역성
    - 크롤링 작업을 수행하는 서버를 크롤링 대상 서버와 지역적으로 가깝게 배치
    - 크롤 서버, 캐시, 큐, 저장소 등 대부분의 컴포넌트에 적용 가능
4. 짧은 타임아웃
    - 응답이 느리거나 응답하지 않는 서버를 오래 기다리지 않도록 최대 대기시간을 미리 설정
    - 정해진 시간 동안 서버가 응답하지 않으면 다운로드를 중단하고 다음 페이지로 이동

**안정성**

- 안정 해시
    - 다운로더 서버에 부하를 분산할 때 적용
    - 다운로더 서버를 쉽게 추가하거나 삭제할 수 있음
- 크롤링 상태 및 수집 데이터 저장
    - 장애 발생 후 쉽게 복구할 수 있도록 크롤링 상태와 수집 데이터를 지속성 저장장치에 기록
    - 저장된 데이터를 로딩하면 중단된 크롤링을 쉽게 재시작할 수 있음
- 예외 처리
    - 대규모 시스템에서 오류는 흔하게 발생
    - 예외가 발생해도 전체 시스템이 중단되지 않고 작업을 이어갈 수 있어야 함
- 데이터 검증
    - 시스템 오류를 방지하기 위한 중요 수단

**확장성**

- 새로운 형태의 콘텐츠를 쉽게 지원할 수 있도록 새로운 모듈을 끼워 넣는 구조로 설계
    - PNG 다운로더: PNG 파일을 다운로드하는 플러그인 모듈
    - 웹 모니터: 웹을 모니터링하여 저작권이나 상표권 침해를 막는 모듈

**문제 있는 콘텐츠 감지 및 회피**

1. 중복 콘텐츠
    - 웹 콘텐츠의 약 30%는 중복
    - 해시나 체크섬을 사용하면 중복 콘텐츠를 쉽게 탐지할 수 있음
2. 거미 덫
    - 크롤러를 무한 루프에 빠뜨리도록 설계한 웹 페이지
    - 무한히 깊은 디렉터리 구조를 포함하는 링크 등이 해당
    - URL의 최대 길이를 제한하면 회피할 수 있음
    - 모든 종류의 덫을 피할 수 있는 해결책은 없음
    - 사람이 수작업으로 확인한 뒤 해당 사이트를 탐색 대상에서 제외하거나 URL 필터 목록에 추가할 수 있음
3. 데이터 노이즈
    - 광고, 스크립트 코드, 스팸 URL 등은 크롤러에 도움이 되지 않으므로 가능하면 제외

**추가로 논의할 수 있는 사항**

- 서버 측 렌더링을 적용하여 자바스크립트나 AJAX를 통해 동적으로 생성되는 링크 처리
- 스팸 방지 컴포넌트를 사용해 품질이 낮거나 스팸성인 페이지 필터링
- 데이터베이스 다중화 및 샤딩을 적용해 데이터 계층의 가용성, 규모 확장성, 안정성 향상
- 서버를 무상태로 만들어 수평적 규모 확장성 확보
- 가용성, 일관성, 안정성
- 수집한 데이터와 분석 결과를 활용한 시스템 조정
