# 웹 크롤러 설계

## 1. 웹 크롤러란?

웹에 **새로 올라오거나 갱신된 콘텐츠를 찾아내는** 프로그램. 몇 개의 웹 페이지에서 시작해 그 안의 링크를 따라가며 새로운 콘텐츠를 수집한다.

| 용도 | 설명 | 예시 |
|---|---|---|
| 검색 엔진 인덱싱 | 웹 페이지를 모아 검색 엔진을 위한 로컬 인덱스를 만든다 | 구글 검색 엔진 |
| 웹 아카이빙 | 나중에 사용할 목적으로 장기 보관하기 위해 정보를 모은다 | 국립 도서관 |
| 웹 마이닝 | 인터넷에서 유용한 지식을 도출해 낸다 | 금융 기업의 기업 정보 분석 |
| 웹 모니터링 | 저작권, 상표권 등이 침해되는 사례를 모니터링한다 | 저작권 침해 탐지 |

## 2. 설계 시 고려할 변수

- **용도**: 검색 엔진 인덱싱? 웹 마이닝?
- **규모**: 매달 몇 개의 페이지를 수집하나? (예: 월 10억 개)
- **콘텐츠 종류**: HTML만? 이미지, PDF 같은 파일도?
- **신규·변경 페이지**: 새로 생기거나 수정된 페이지도 다시 수집해야 하나?
- **저장 기간**: 수집한 페이지를 얼마나 보관하나? (예: 5년)
- **중복 콘텐츠**: 내용이 같은 페이지는 무시해도 되나?

**좋은 크롤러가 갖춰야 할 속성**

| 속성 | 의미 |
|---|---|
| 규모 확장성 | 병렬 처리로 거대한 웹을 효율적으로 수집 |
| 안정성 | 잘못된 HTML, 응답 없는 서버, 악성 링크에도 멈추지 않음 |
| 예의 | 한 사이트에 짧은 시간 동안 너무 많은 요청을 보내지 않음 |
| 확장성 | 새 콘텐츠 형식을 지원할 때 전체를 다시 설계하지 않아도 됨 |

**개략적 규모 추정** (월 10억 페이지, 평균 500KB, 5년 보관)

- QPS: 10억 ÷ 30일 ÷ 24시간 ÷ 3600초 ≈ **400** (최대 약 800)
- 월 저장 공간: 10억 × 500KB = **500TB**
- 5년 저장 공간: 500TB × 12 × 5 = **30PB**

## 3. 구성 요소

```
시작 URL 집합 → 미수집 URL 저장소 → HTML 다운로더 (← 도메인 이름 변환기)
→ 콘텐츠 파서 → 중복 콘텐츠인가? → 콘텐츠 저장소
→ URL 추출기 → URL 필터 → 이미 방문한 URL인가? → 미수집 URL 저장소로
```

### 시작 URL 집합

- 크롤링을 시작하는 출발점
   - 예: 한 대학 웹사이트를 크롤링한다면 그 대학 도메인 이름이 붙은 모든 페이지의 URL에서 시작
- 전체 웹을 크롤링한다면 URL 공간을 나눠서 고른다
   - **지역별**: 나라마다 인기 있는 웹사이트가 다르다
   - **주제별**: 쇼핑, 스포츠, 건강 등
- 정답은 없다. **의도에 맞는 초기 URL 집합**을 고르는 방향성이 중요하다.

### 미수집 URL 저장소 (URL Frontier)

- 아직 다운로드하지 않아서 **앞으로 다운로드할 URL**을 저장·관리하는 곳
- 단순 FIFO 큐가 아니라 우선순위·신선도·예의를 반영해 설계한다

### HTML 다운로더 / 도메인 이름 변환기

- 다운로더: 인터넷에서 웹 페이지를 내려받는다
- 도메인 이름 변환기: URL을 IP 주소로 변환한다 (DNS 조회)

### 콘텐츠 파서

- 다운로드한 웹 페이지를 **파싱·검증**한다
- 이상한 웹 페이지(깨진 HTML, 악성 코드 포함 등)를 걸러내 **저장 공간 낭비를 막는다**

### 중복 콘텐츠인가?

- 실제로 웹 페이지의 **약 29%는 중복된 내용**이다
- 중복을 걸러내야 저장 공간과 데이터 처리 시간을 줄일 수 있다
- 페이지를 통째로 비교하면 느리므로 **해시값(체크섬)**을 비교한다

### URL 추출기

- HTML에서 링크를 골라낸다
- 상대 경로는 절대 경로로 변환한다 (예: `/wiki/A` → `https://ko.wikipedia.org/wiki/A`)

### URL 필터

- 크롤링에서 **배제할 대상**을 정의한다
   - 특정 확장자, 접속 시 오류가 나는 URL, 접근 제외 목록에 포함된 URL 등

### 이미 방문한 URL인가?

- 이미 방문했거나 저장소에 있는 URL은 다시 추가하지 않는다
   - 같은 URL을 여러 번 처리하는 낭비와 **무한 루프**를 막는다
- 추적용 자료구조: **블룸 필터**, **해시 테이블**

## 4. 탐색 전략: DFS vs BFS

웹은 페이지를 노드, 링크를 간선으로 하는 **유향 그래프**다.

- **DFS**: 그래프가 얼마나 깊을지 가늠할 수 없어 부적합
- **BFS**: 일반적으로 사용하지만 두 가지 문제가 있다
   1. **한 페이지의 링크 대부분이 같은 서버로 돌아간다** → 같은 호스트에 요청이 몰려 무례한 크롤러가 됨
   2. **모든 URL을 공평하게 대한다** → 실제로는 중요도가 다르다 (개인 블로그 글 vs 박사 논문)

→ **미수집 URL 저장소**를 잘 설계해 해결한다.

**예의 (Politeness)**
- 짧은 시간에 한 서버로 너무 많은 요청을 보내면 무례한 크롤러 (DoS 공격으로 간주될 수도 있음)
- 해결: **호스트별로 큐를 따로 두고**, 한 큐는 한 작업 스레드만 처리하며 요청 사이에 지연 시간을 둔다

**우선순위 (Priority)**
- 페이지랭크, 트래픽 양, 갱신 빈도 등으로 **유용한 페이지를 먼저** 수집한다

**신선도 (Freshness)**
- 웹 페이지는 계속 추가·삭제·변경되므로 주기적으로 **재수집**해야 한다
- 변경 이력을 활용하고, 우선순위가 높은 페이지를 더 자주 재수집한다

## 5. robots.txt

- **로봇 제외 프로토콜**: 웹사이트가 크롤러와 소통하는 표준
- 크롤링 전에 이 파일을 읽어 **수집해도 되는 페이지와 안 되는 페이지**를 확인한다
- 사이트의 요청을 존중하면서 필요 없는 페이지를 건너뛸 수 있다
- 매번 받지 않도록 **주기적으로 다운로드해 캐시**에 보관한다

```
User-agent: Googlebot
Disallow: /creatorhub/*
Disallow: /rss/people/*/reviews
```

## 6. 문제 있는 콘텐츠 감지 및 회피

### 중복 콘텐츠 → 체크섬

- **체크섬(Checksum)**: 데이터 전체를 계산해 만든 **짧은 고정 길이의 요약값**
- 내용이 같으면 체크섬도 같고, 한 글자만 달라져도 체크섬이 크게 달라진다
- 큰 페이지를 통째로 비교하는 대신 **짧은 값만 비교**하면 된다
- 대표 알고리즘: CRC32, MD5, SHA-1, SHA-256

```
페이지 A (500KB) → 체크섬: 9f86d081...
페이지 B (500KB) → 체크섬: 9f86d081...  ← 같음 → 중복, 저장 안 함
페이지 C (500KB) → 체크섬: 3c59dc04...  ← 다름 → 새 콘텐츠, 저장
```

### 거미 덫 (Spider Trap)

- 크롤러를 **무한 루프에 빠뜨리도록** 설계된 웹 페이지
   - 예: `spidertrapexample.com/foo/bar/foo/bar/foo/bar/...`
- 대응
   - **URL 최대 길이를 제한**한다
   - 모든 덫을 자동으로 피할 수는 없으므로 **수작업으로 확인**해 필터 목록에 추가한다

### 데이터 노이즈

- 광고, 스크립트 코드, 스팸 URL처럼 가치 없는 콘텐츠는 가능하면 제외한다

## 7. 최적화 기법

**성능**

| 기법 | 설명 |
|---|---|
| 분산 크롤링 | 작업을 여러 서버에 분산하고, 각 서버는 여러 스레드로 다운로드 |
| 도메인 이름 변환 결과 캐시 | DNS 조회는 느리고 동기적이라 병목 → 결과를 캐시하고 주기적으로 갱신 |
| 지역성 | 크롤링 서버를 대상 사이트와 가깝게 배치해 다운로드 시간 단축 |
| 짧은 타임아웃 | 최대 응답 대기 시간을 정해 두고, 응답 없는 서버는 건너뜀 |

**안정성**

| 기법 | 설명 |
|---|---|
| 안정 해시 | 다운로더 서버 간 부하를 분산하고, 서버 추가·삭제를 쉽게 함 |
| 크롤링 상태 및 수집 데이터 저장 | 장애 시에도 쉽게 복구하도록 지속적으로 저장 장치에 기록 |
| 예외 처리 | 예외가 발생해도 전체 시스템이 중단되지 않고 작업을 이어감 |
| 데이터 검증 | 시스템 오류를 방지하기 위한 중요 수단 |
