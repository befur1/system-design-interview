## 9장 요약

웹 크롤러(Web crawler)는 로봇(robot) 또는 스파이더(spider)라고 부름

검색 엔진에서 널리 쓰는 기술로, 웹에 새로 올라오거나 갱신된 콘텐츠를 찾아내는 것이 주된 목적

- 검색 엔진 인덱싱: 크롤러의 가장 보편적인 용례. 크롤러는 웹 페이지를 모아 검색 엔진을 위한 로컬 인덱스를 만듬
- 웹 아카이빙: 나중에 사용할 목적으로 장기보관하기 위해 웹에서 정보를 모으는 절차를 의미
- 웹 마이닝: 인터넷에서 유용한 정보를 모아서 유용한 지식으로 도출해 내는 것
- 웹 모니터링: 크롤러를 사용하면 인터넷에서 저작권이나 상표권이 침해되는 사례를 확인

### 1. 문제 이해 및 설계 범위 확정

1. URL 집합이 입력으로 주어지면, 해당 URL들이 가리키는 모든 웹 페이지를 다운로드함
2. 다운받은 웹 페이지에서 URL들을 추출함
3. 추출된 URL들을 다운로드할 URL에 추가하고 위의 과정을 반복함

#### 웹 크롤러가 만족시켜야할 속성

- 규모 확장성: 수십억 개의 페이지가 존재하니 병행성을 활용하여 효과적으로 웹 크롤링을 해야 함
- 안정성: 비정상적인 입력이나 환경에 잘 대응할 수 있어야 함
- 예절: 크롤러가 너무 짧은 시간 동안 너무 많은 요청을 보내서는 안 됨
- 확장성: 새로운 형태의 콘텐츠를 지원하기가 쉬워야 함

### 2. 개략적 설계안 제시 및 동의 구하기

#### 시작 URL 집합

웹 크롤러가 크롤링을 시작하는 출발점

- 크롤링 시작 세팅 방식
1. 홍익대학교 사이트로부터 찾아 나갈 수 있는 모든 웹 페이지를 크롤링하는 가장 직관적인 방법:  도메인에 학교 이름이 붙은 모든 페이지의 URL을 시작 URL로 하는 것
2. 주제별로 다른 시작 URL 부분집합으로 나누는 것: URL 공간을 쇼핑, 스포츠, 건강 등등의 주제별로 세분화

#### 미수집 URL 저장소

크롤링 상태가 (1) 다운로드할 URL, (2) 다운로드된 URL의 두 가지로 나뉨

(1)의 상태를 저장 관리하는 컴포넌트를 미수집 URL 저장소(URL frontier)라고 부름

#### HTML 다운로더

HTML 다운로더는 인터넷에서 웹 페이지를 다운로드하는 컴포넌트. 

다운로드할 페이지의 URL ←미수집 URL 저장소가 제공

#### 도메인 이름 변환기

도메인 이름을 가지고 있는 URL에 대응되는 IP 주소로 변환

#### 콘텐츠 파서

크롤링 서버와 분리된 독립된 컴포넌트로 웹 페이지를 다운로드 후 파싱과 검증의 절차를 담당

#### 중복 콘텐츠

데이터 중복 및 처리 시간을 줄이기 위해 웹 페이지의 해시 값의 비교를 통해 빠르게 HTML 두 문서를 비교

#### 콘텐츠 저장소

HTML 문서를 보관하는 시스템으로서 구현하기 위해서 여러 가지를 종합적으로 고려해야 함

#### URL 추출기

HTML 페이지를 파싱하여 링크들을 골라내는 역할을 함

상대 경로에 전부 `https://en.wikipedia.org`를 붙여 절대 경로로 변환

#### URL 필터

특정한 콘텐츠 타입이나 파일 확장자를 갖는 URL, 접속 시 오류가 발생하는 URL, 접근 제외 목록에 포함된 URL 등을 크롤링 대상에서 배제하는 역할을 함

#### 이미 방문한 URL?

블룸 필터나 해시 테이블과 같은 이미 방문한 URL을 추적하는 자료 구조를 사용

#### URL 저장소

이미 방문한 URL을 보관하는 저장소

### 3. 상세 설계

웹은 Directed Graph로서 DFS와 BFS 둘 중에 BFS를 선호함(BFS는 [FIFO] 큐를 사용하는 알고리즘).

BFS 방식의 문제점 2가지

1. ‘예의 없는’ 크롤러로 간주
- 한 페이지에서 URL 추출기로 나온 링크의 상당수가 같은 서버로 되돌아 감
    
    ← 링크들을 병렬로 처리하다 보면 같은 서버는 수많은 요청으로 과부하에 걸림
    
1. URL 간에 우선순위가 없음

#### 미수집 URL 저장소

**예의(politeness)를 갖춘 크롤러**

짧은 시간 안에 너무 많은 요청을 보내는 것은 무례한 일이며, DoS 공격으로 간주되기도 함

그래서 예의 바른 크롤러의 한 가지 원칙은, 동일 웹 사이트에 대해서 한 번에 한 페이지만 요청하는 것

다운로드를 숭행하는 작업 쓰레드는 별도의 FIFO 큐를 가짐

큐 라우터가 매핑 테이블을 보고 URL을 큐에 올려놓음 → 큐 선택기가 순회하면서 URL을 꺼내서 작업 쓰레드에게 전달 → 작업 쓰레드는 URL 다운로드 작업을 수행

**우선순위를 갖춘 크롤러**

유용성에 따라 URL의 우선 순위를 나눌 때는 페이지랭크(웹 페이지의 중요도를 측정하는 알고리즘), 트래픽 양, 갱신 빈도 등 다양한 척도를 사용할 수 있음

URL을 입력 → 순위결정장치로 우선순위를 계산 → 우선순위별로 큐가 하나씩 할당 → 우선순위가 높으면 큐 선택기가 자주 뽑음

**신선도를 갖춘 크롤러**

웹 페이지는 수시로 추가, 삭제, 변경됨. 그래서 이미 다운로드한 페이지라고 해도 주기적으로 재수집이 필요

→ 웹 페이지의 변경 이력 활용, 우선순위 활용으로 중요한 페이지는 좀 더 자주 재수집

#### HTML 다운로더

HTML 다운로더는 HTTP 프로토콜을 통해 웹 페이지를 내려 받음

**Robot.txt**

웹페이지가 크롤러와 소통하는 표준적인 방법으로, 이 파일에는 수집해도 되는 페이지 목록이 들어 있음

**HTML 다운로더의 성능 최적화**

1. 분산 크롤링: 미수집 URL 저장소가 크롤링 작업을 여러 서버에 분산하는 방법
2. 도메인 이름 변환 캐시: 도메인과 IP 주소 사이의 관계를 캐시에 보관
3. 지역성: 크롤링 서버가 크롤링 대상 서버와 지역적으로 가깝게 둠
4. 짧은 타임아웃: 어떤 웹 서버가 응답이 느리거나 응답하지 않을 때를 대비해서 기다릴 시간을 미리 정함

**HTML 다운로더의 성능 안정성**

- 안정 해시: 다운로더 서버들에 부하를 분산할 때 적용. 이를 통해 다운로더 서버를 쉽게 추가 및 삭제가 가능함
- 크롤링 상태 및 수집 데이터 저장: 장애가 발생한 경우에도 쉽게 복구살 수 있도록 기록해두는 것
- 예외 처리: 예러가 발생해도 시스템이 중단되는 일 없이 작업이 진행되게 해야 함
- 데이터 검증: 시스템 오류를 방지하기 위한 중요 수단 가운데 하나

**HTML 다운로더의 확장성**

새로운 모델을 끼워 넣음으로써 새로운 형태의 콘텐츠를 지원할 수 있도록 설계해야 함

**HTML 다운로더의 문제 있는 콘텐츠 감지 및 회피**

1. 중복 콘텐츠: 해시나 체크섬을 사용하면 쉽게 탐지 가능
2. 거미 덫: 크롤러를 무한 루프에 빠뜨리도록 설계한 웹 페이지
3. 데이터 노이즈: 가치가 없는 광고나 스팸 URL 같은 건 크롤러에게 도움이 되지 않으니 제외해야 함

### 예의의 반대편

9장의 예의(politeness)는 **내가 보내는 쪽일 때**의 이야기임. 짧은 시간에 너무 많은 요청을 보내지 말고, 한 사이트에 한 번에 한 페이지만 요청하라는 것

그런데 데모데이 프로젝트(HAMA)에서 내가 맡은 Paddle 결제 웹훅은 **받는 쪽**임. 거기서 반대 상황을 만났음

```java
// 대시보드에서 다른 이벤트까지 구독해 두어도 200 으로 받고 넘깁니다.
// 에러를 내면 Paddle 이 계속 재전송합니다.
default -> log.info("[Payment] 처리하지 않는 웹훅 - type: {}", eventType);
```

처리할 생각이 없는 이벤트에 400이나 500을 돌려주면, **Paddle 의 재시도 정책이 그대로 나를 때리는 트래픽이 됨**. 구독만 해두고 안 쓰는 이벤트가 계속 재전송되는 거라, 조용히 200을 주고 넘길

|  | 9장 크롤러 | HAMA 웹훅 |
| --- | --- | --- |
| 내 위치 | 보내는 쪽 | **받는 쪽** |
| 과부하를 막는 방법 | 내가 천천히 보냄 | **내가 조용히 200을 줌** |
| 상대방 입장 | 내가 예의 없으면 차단당함 | 내가 에러 내면 상대가 더 보냄 |

9장은 보내는 쪽 예의만 다루는데, **받는 쪽도 상대의 재시도를 멈춰줄 책임이 있음**. 예의가 한쪽이 아니라 양쪽 일이었던 것

그리고 여기서 상태 코드의 의미가 달라짐. 보통 상태 코드는 "이 요청이 어떠했는지"를 알리는 건데, 웹훅에선 **"다시 보낼지 말지"를 지시하는 신호**로 쓰임
