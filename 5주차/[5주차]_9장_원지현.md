# [5주차] 9장 정리 - 원지현
# 9장_ 웹 크롤러 설계

## 웹 크롤러란
웹 크롤러는 웹페이지를 다운로드하고, 그 안의 링크를 따라가며 새로운 콘텐츠를 수집하는 프로그램임.
- 주요 용도: 검색 엔진 인덱싱, 웹 아카이빙, 웹 마이닝, 웹 모니터링
- 기본 알고리즘: URL 집합의 페이지를 다운로드 → 페이지에서 URL 추출 → 추출한 URL을 다운로드 목록에 추가하고 반복

## 설계 범위와 규모
- 검색 엔진 인덱싱용으로 매달 10억 개의 HTML 페이지를 수집하고 5년간 저장함.
- 초당 약 400페이지(최대 800) 수집, 5년간 약 30PB 저장 필요
- 좋은 크롤러의 조건: 규모 확장성, 안정성, 예절, 확장성

## 주요 컴포넌트와 작업 흐름
- 시작 URL을 미수집 URL 저장소에 넣음.
- HTML 다운로더가 URL을 가져와 도메인 이름 변환기로 IP를 찾고 페이지를 다운로드함.
- 콘텐츠 파서가 페이지를 검증함.
- 중복 콘텐츠 확인: 페이지 내용의 해시 값으로 이미 저장한 콘텐츠인지 확인하고, 중복이면 버림.
- 처음 보는 콘텐츠면 저장한 뒤 URL 추출기로 링크를 추출하고 URL 필터로 거름.
- 이미 방문한 URL 확인: 블룸 필터나 해시 테이블로 확인하고, 처음 보는 URL만 미수집 URL 저장소에 추가함.

## 상세 설계

탐색 방식
- 웹은 유향 그래프와 같으며, 깊이를 알기 어려운 DFS 대신 BFS를 사용함.
- 단순 BFS는 같은 호스트에 요청이 몰리고(예절 위반), 우선순위가 없다는 문제가 있음.

미수집 URL 저장소
- 예의: 같은 호스트의 URL은 같은 큐에 넣고, 큐마다 하나의 작업 스레드가 지연 시간을 두며 처리함.
- 우선순위: 페이지랭크, 트래픽, 갱신 빈도 등으로 중요한 URL을 먼저 처리함.
- 신선도: 변경 이력과 우선순위를 활용해 중요한 페이지일수록 더 자주 재수집함.
- 저장: 대부분 디스크에 두고, 메모리 버퍼로 입출력을 처리함.

HTML 다운로더
- Robots.txt를 확인해 수집이 허용된 페이지만 다운로드하며, 이 파일은 캐시해둠.
- 성능 최적화: 분산 크롤링, DNS 결과 캐시, 지역성 활용, 짧은 타임아웃

안정성과 확장성
- 안정 해시로 다운로더 서버 간 부하를 분산하고, 서버를 쉽게 추가·삭제함.
- 크롤링 상태를 저장해 장애 시 복구하고, 예외가 발생해도 전체가 멈추지 않게 함.
- 새로운 콘텐츠 형식은 모듈을 추가하는 방식으로 지원함.

문제 있는 콘텐츠 회피
- 중복 콘텐츠: 해시나 체크섬으로 탐지함.
- 거미 덫: 무한히 깊은 링크 구조로, URL 최대 길이 제한 등으로 회피함.
- 데이터 노이즈: 광고, 스팸 등 가치 없는 콘텐츠는 제외함.

## 추가 학습: 크롤링을 활용한 서비스 예시
책의 웹 크롤러는 링크를 따라 웹 전체를 탐색하는 범용 크롤러이지만, 실제 프로젝트에서는 정해진 사이트만 주기적으로 수집하는 특정 대상 크롤러 형태로 많이 활용함.

예시 1: 학교 공지사항 통합 서비스
- 학교 공식 홈페이지, 국제교류처, 교양과, 학과 홈페이지 등 흩어진 공지사항을 한곳에 모아 보여주는 서비스
- 책의 개념 적용
    - 시작 URL: 각 기관의 공지사항 목록 페이지로 고정함. 웹 전체를 탐색할 필요가 없으므로 BFS보다 목록 페이지 재방문이 핵심임.
    - 신선도: 공지가 자주 올라오는 곳은 짧은 주기로, 드물게 올라오는 곳은 긴 주기로 재방문함.
    - 예의: 학교 서버는 규모가 작은 경우가 많으므로 요청 간격을 충분히 두고, robots.txt를 확인함.
    - 새 글 감지: 게시글 번호나 URL을 저장해두고, 이미 방문한 URL인지 확인해 새 공지만 수집함.
    - 중복 제거: 같은 공지가 공식 홈페이지와 학과 홈페이지에 함께 올라오는 경우, 제목과 본문의 해시 값으로 중복을 걸러냄.
    - 확장성: 사이트마다 HTML 구조가 다르므로, 사이트별 파서를 모듈로 분리해 새 기관을 쉽게 추가할 수 있게 함.
    - 안정성: 사이트 개편으로 HTML 구조가 바뀌면 파싱이 실패할 수 있으므로, 예외 처리와 실패 감지가 필요함.
- 새 공지가 감지되면 사용자에게 푸시 알림을 보내도록 확장할 수 있음. (10장 알림 시스템과 연결)

예시 2: 공동구매 사이트 모음 서비스
- 여러 공동구매 사이트의 상품, 가격, 마감일을 한곳에서 비교할 수 있게 모아 보여주는 서비스
- 책의 개념 적용
    - 신선도: 가격이나 재고, 마감 여부가 자주 바뀌므로 인기 상품일수록 짧은 주기로 재방문함.
    - 중복 제거: 같은 상품이 여러 사이트에 올라온 경우를 구분하고 묶어서 보여줌.
    - 예의: 여러 사이트에 동시에 요청하므로 사이트별로 요청 간격을 따로 관리함.
- 주의할 점: 상업 사이트는 이용약관에서 크롤링을 금지하는 경우가 있으므로, robots.txt와 약관을 확인하고 공식 API가 있다면 API를 우선 사용함.

정리
- 범용 크롤러는 넓게 탐색하는 것이 핵심이지만, 특정 대상 크롤러는 정해진 페이지를 얼마나 자주, 예의 바르게, 중복 없이 수집하느냐가 핵심임.
